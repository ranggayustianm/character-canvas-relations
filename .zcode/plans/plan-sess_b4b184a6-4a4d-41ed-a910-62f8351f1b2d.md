## Step 1 — Persist hardening in `src/lib/store.ts` (§3.3 Tier A)

- `partialize: (s) => ({ boards: s.boards })` — explicit exclusion of actions.

## Step 2 — Drag-frame persistence fix in `src/components/Canvas.tsx` (§3.3 Tier A / §4.1 #1)
- In `handleNodesChange` (Canvas.tsx:50): filter out `change.type === "position" && change.dragging` before calling `applyNodeChanges`; selection/dimension/remove changes still flow through. React Flow v12 keeps drag positions in its internal store during the gesture and emits a final `position` change with `dragging: false` on stop, so the node still follows the cursor and the store gets exactly one write per drag (verified in installed `@xyflow/system` types).
- Add belt-and-braces `onNodeDragStop` that commits final positions for **all** dragged nodes (v12 signature is `(event, node, nodes)` — multi-node group drags must not lose the others' positions).
- §4.1 nit: wrap `handleNodesChange`/`handleEdgesChange` in `useCallback`.
- Verification note: if a manual drag test shows nodes snapping back during drag (would mean XYFlow re-syncs from the unchanged prop reference), fall back to the alternative shape — keep applying changes per frame but debounce the store write to ~250 ms + on drag-stop.
